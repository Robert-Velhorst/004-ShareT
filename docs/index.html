Trello work.
Shared access.

ShareT is a software project for sharing selected Trello cards and lists with people who do not have a Trello account.

Collaborators use a shared page. The project owner keeps the conversation in Trello.

Understand the workflow →

How the pieces fit together.

  1. 01

    Select the work

    The Trello owner chooses a card or list and creates a shared link in a running ShareT installation.

  2. 02

    Contribute through ShareT

    The collaborator opens the link. Posting updates requires a name and email verification, but no Trello account.

  3. 03

    Reply inside Trello

    A configured relay member posts the update with the collaborator’s name. The owner replies on the Trello card.

Two sides.
One conversation.

The project is designed to keep updates with the work, even when collaborators cannot use Trello directly.

With the required services configured, ShareT can email a Trello reply to the verified participant. A Trello Power-Up panel is not required.

Access controls.
Clear boundaries.

  • Selected cards or lists

    Links expose the selected work according to their settings, not a separate Trello account for each collaborator.

  • Password and expiry options

    Owners can limit access to a shared link. Treat the link itself as sensitive when sharing private work.

  • Verified participation

    Names and verified email addresses connect comments with participants in the running application.

What a running installation needs

  • A Node.js server and stable HTTPS address.
  • Trello API credentials and access to the relevant boards.
  • A separate relay member for owner notifications.
  • An email service for verification and reply emails.
  • Operational care for secrets, stored data, and backups.

GitHub Pages hosts this information only. It does not run the ShareT application, process payments, or deliver notifications.

Questions about the project.

Is this the ShareT application?

No. This is an informational project website. It explains the software and links to its source and documentation. There is no account registration, payment processing, or live collaboration on this site.

Do collaborators need a Trello account?

No. In a configured ShareT installation, they participate through a shared link. The owner and relay member still need their own Trello access.

Can the owner reply from a phone?

Yes, the workflow supports normal comments from the Trello mobile app. When several participants are waiting, use the intended person’s full name, or start with their unique first name. Email delivery depends on the installation’s configuration.

Are notifications guaranteed?

No. Delivery depends on Trello permissions, the relay identity, subscription and notification settings, email configuration, and provider availability. The documentation explains setup and known limitations; the examples here are not evidence of live delivery.

Does this website collect my information?

This page has no forms, analytics, cookies, or application storage. GitHub, as the hosting provider, may process visitor information such as IP addresses for security. The separate ShareT application processes information needed for its collaboration features.
